## 3b. Short definitions

- **opencode**: AI programming assistant that runs in a command-line window, reads a prompt then generates code and runs check commands.
- **API**: the programming interface of the external service, here the service that replies using the `gpt-4o-mini` model, accessed with the key the user enters.
- **endpoint**: a specific HTTP path on the server, for example `/api/setup/status`.
- **venv**: a private virtual Python environment for the project, created with `py -m venv .venv`.
- **pytest**: the automated test runner tool for Python, using `test_` functions and `pytest.raises`.
- **DDD**: layered domain-driven architecture, dependency arrows point inward, the domain does not depend on the outer framework.
- **TDD**: write the test first, see red, write the minimal code, see green, then continue.
- **MUI**: a React interface library containing components such as `Dialog`, `TextField`, `Paper`, `AppBar`, loaded from CDN, no build step needed.
- **formal spec**: a formal specification using PRE, POST, INV, ERR, KILL and logic notation to describe checkable conditions.
- **use case**: a function expressing exactly one use case of the business, here located in the application layer.
- **port**: an abstract class in the domain layer describing what must be done, not yet knowing how.
- **fake**: a double class used in tests, records calls and allows error injection.
- **`UpstreamError`**: an error of the external service, carrying an HTTP status code and a Vietnamese message.
- **`session_id`**: the conversation session identifier string, matching `^[A-Za-z0-9-]{8,64}$`.
- **`empty_reply`**: the internal error code when the model returns an empty string, mapping to HTTP 502.
- **`call`**: one function call recorded by a fake so the test can assert the order and the arguments.

# BLUEPRINT v4: web chatbot, 10 prompts, DDD, TDD, MUI, first-time API key entry on the page

User lock-in 2026-10-07: the prompt IS the blueprint; an AI that reads all 10 prompts (P0 through P9) can build the chatbot; each prompt is at least 5,000 words, written in formal specification style, covering every case; the first thing to do when the chatbot runs for the first time is TO ASK FOR THE API KEY, send it to the server, the server stores it, and then it runs.

## B1. Goal and first-run flow
- Platform: Windows 11, PowerShell, Python invoked via `py`, coding assistant is opencode, responding model is `gpt-4o-mini` via the OpenAI API (external API).
- First-run flow:
  1. The learner runs `py run.py`; the server starts at `http://127.0.0.1:2610` WHEN THERE IS NO API KEY YET (must not crash).
  2. The browser opens the page; `main.js` calls `GET /api/setup/status`.
  3. It returns `{"configured": false}` ⇒ show the MUI dialog "Nhập khóa API" (password field + Save button).
  4. The learner pastes the key, clicks Save ⇒ `POST /api/setup` with `{"api_key": "<key>"}`.
  5. The server validates the key format, writes it into the `.env` file (line `OPENAI_API_KEY=`) atomically, updates the process memory, returns `{"ok": true}`; it must NEVER return the key.
  6. The page closes the dialog and shows the chat frame; chat runs immediately, no restart needed.
  7. Subsequent runs: `status` returns `{"configured": true}` ⇒ go straight to the chat frame.
- The key lives only in `.env`; not in logs, not in `memory.json`, not in responses, not in errors.

## B4. Domain
- `Message`: frozen dataclass `role: str` (only `"human"` or `"ai"`), `content: str` (non-empty). Wrong ⇒ `ValueError`.
- `trim_history(messages: list[Message], limit: int) -> list[Message]`: returns the LAST `limit` messages, preserving order; `limit <= 0` ⇒ `ValueError`; empty list ⇒ empty; fewer than `limit` ⇒ return all; does not modify the input list.
- `errors.py`: `ApiKeyMissing`, `InvalidApiKey`, `InvalidMessage`, `InvalidSession`, `UpstreamError(status: int, message: str)`; all inherit `ChatbotError(Exception)`.
- Ports (abstract classes `abc.ABC`):
  - `MemoryRepository`: `get(session_id: str) -> list[Message]`, `append(session_id: str, messages: list[Message]) -> None`, `reset(session_id: str) -> None`.
  - `ChatModel`: `reply(system_prompt: str, history: list[Message], user_text: str) -> str`.
  - `ApiKeyStore`: `is_configured() -> bool`, `get() -> str`, `save(api_key: str) -> None`.

## B5. Application (use cases, one function per file)
- `validate_session_id(session_id) -> str`: matches `^[A-Za-z0-9-]{8,64}$`, otherwise `InvalidSession`.
- `validate_message(text) -> str`: trims leading and trailing whitespace; empty ⇒ `InvalidMessage`; longer than 4000 characters ⇒ `InvalidMessage`.
- `validate_api_key(api_key) -> str`: trims whitespace; length 20 to 200; only printable ASCII characters, NO whitespace inside; wrong ⇒ `InvalidApiKey`. Do NOT check the vendor prefix.
- `get_setup_status(store) -> dict`: `{"configured": store.is_configured()}`.
- `configure_api_key(store, api_key) -> None`: `store.save(validate_api_key(api_key))`.
- `send_message(repo, model, store, system_prompt, max_messages, session_id, text) -> str`:
  1. `sid = validate_session_id(...)`, `msg = validate_message(...)`.
  2. `store.is_configured()` false ⇒ `ApiKeyMissing`.
  3. `history = trim_history(repo.get(sid), max_messages)` (if empty, skip trimming).
  4. `reply = model.reply(system_prompt, history, msg)`.
  5. `repo.append(sid, [Message("human", msg), Message("ai", reply)])` ONLY after `reply` exists; a model error ⇒ write NOTHING to memory.
  6. return `reply`.
- `reset_conversation(repo, session_id) -> None`: validate `session_id`, then `repo.reset(sid)`; resetting a non-existent session is a silent success.

## B6. Infrastructure
- `atomic_write_text(path, text)`: writes to a temp file in the same directory then `os.replace`; creates the parent directory if missing; on error ⇒ delete the temp file, rethrow the error.
- `atomic_write_json(path, data)`: `json.dumps(ensure_ascii=False, indent=2)` then `atomic_write_text`.
- `JsonMemoryRepository(path)`: uses `threading.Lock`; file format `{"<session_id>": [{"role": "human", "content": "..."}]}`; missing file ⇒ empty; corrupt file (invalid JSON) ⇒ rename to `memory.json.corrupt-<timestamp>` then start empty, MUST NOT crash; `append` reads then writes atomically within the same lock; stores ALL messages (trimming happens only when reading for the model).
- `load_system_prompt(path) -> str`: reads UTF-8; missing file ⇒ returns a short Vietnamese default, MUST NOT crash; empty file ⇒ also the default.
- `EnvApiKeyStore(env_path)`: `is_configured()` is true exactly when `get()` is non-empty; `get()` reads `OPENAI_API_KEY` from the `.env` file (and from `os.environ` if the file is missing); `save(key)` rewrites the `.env` file keeping the other lines intact, replacing or appending exactly one line `OPENAI_API_KEY=<key>`, writes atomically, updates `os.environ`; write error ⇒ rethrow, MUST NOT leave a half-written file.
- `mask_secret(value) -> str`: returns `"****"` plus the last 4 characters when the length is 12 or more; otherwise `"****"`; used for logs, MUST NEVER write the real key.
- `LangChainChatModel(settings, store)`: each `reply` builds `ChatPromptTemplate.from_messages([("system", system_prompt), MessagesPlaceholder("history"), ("human", "{input}")])`, attaches `ChatOpenAI(model=settings.openai_model, temperature=settings.openai_temperature, timeout=settings.openai_timeout, api_key=store.get())`, converts `Message` to `HumanMessage`/`AIMessage`, returns `.content`; OpenAI error ⇒ `UpstreamError(*map_openai_error(exc))`; the key is read AGAIN on every turn so that no restart is needed after `/api/setup`.
- `map_openai_error(exc) -> tuple[int, str]`: `AuthenticationError`→401 "Khóa API không đúng, nhập lại"; `RateLimitError` (HTTP 429)→503 "Hệ thống đang quá tải, thử lại sau"; `APITimeoutError`→504 "Mô hình trả lời quá lâu"; `APIConnectionError`→502 "Không kết nối được dịch vụ mô hình"; otherwise→500 "Có lỗi không mong đợi".

## B7. Interface (Flask)
- `create_app(deps) -> Flask`: `deps` comprises `settings`, `repo`, `model`, `store`, `system_prompt_loader`; registers 5 routes; `MAX_CONTENT_LENGTH = 16 * 1024`; error handling funnels into JSON.
- Every error returns `{"error": "<code>", "message": "<Vietnamese>"}`; MUST NEVER return a stack trace.
- `require_localhost`: `request.remote_addr` not in `{"127.0.0.1", "::1"}` ⇒ 403 `forbidden`; applied to `/api/setup`.
- `require_json`: missing `Content-Type: application/json` or body not a JSON object ⇒ 415 or 400.
| route | method | request body | success | errors |
|---|---|---|---|---|
| `/` | GET | | `static/index.html` | |
| `/api/health` | GET | | 200 `{"ok": true}` | |
| `/api/setup/status` | GET | | 200 `{"configured": bool}` | |
| `/api/setup` | POST | `{"api_key": str}` | 200 `{"ok": true}` | 400 `invalid_api_key`, 403, 415, 500 `save_failed` |

## 3c. Implementation process (TDD)

Terminology note, explained exactly once for all of P4: **opencode** is a programming assistant that runs in the command-line window and is used to generate code from a formal spec (formal specification, i.e. a spec written with PRE, POST, INV, ERR, KILL and mathematical notation). **API** is the application programming interface; here it is OpenAI's external API. **endpoint** is an HTTP path that the server answers, for example `/api/chat`. **venv** is a Python virtual environment, a separate folder holding installed packages. **pytest** is Python's test framework; it reads functions beginning with `test_`. **DDD** is domain-driven design architecture, splitting the project into `domain`, `application`, `infrastructure`, `interface` with dependency arrows running in one direction. **TDD** is test-driven development, the RED, GREEN, REFACTOR loop. **MUI** is the Material UI interface library, used in P7.

Algorithm in pseudocode:

```text

    GHI calls += ("get", session_id) ; RETURN bản sao của data[session_id] hoặc DANH SÁCH RỖNG
```

`get` returns a copy and not a reference to the original list, so tests can assert that `send_message` does not modify memory unintentionally. `reset` uses `pop(session_id, None)`, so a session that does not exist yet still succeeds silently, exactly as in B5.

```python
"""Bản giả MemoryRepository cho tầng application."""
from __future__ import annotations

from dataclasses import dataclass, field

from src.chatbot.domain.errors import ChatbotError
from src.chatbot.domain.message import Message
from src.chatbot.domain.ports.memory_repository import MemoryRepository


@dataclass
class FakeMemoryRepository(MemoryRepository):
    data: dict[str, list[Message]] = field(default_factory=dict)
    calls: list[tuple[str, str]] = field(default_factory=list)
    fail_on_append: bool = False

    def get(self, session_id: str) -> list[Message]:
        self.calls.append(("get", session_id))
        return list(self.data.get(session_id, []))

    def append(self, session_id: str, messages: list[Message]) -> None:
        self.calls.append(("append", session_id))
        if self.fail_on_append:
            raise ChatbotError("append bị lỗi giả lập")
        self.data.setdefault(session_id, []).extend(messages)

    def reset(self, session_id: str) -> None:
        self.calls.append(("reset", session_id))
        self.data.pop(session_id, None)

    def methods_called(self) -> list[str]:
        return [name for name, _ in self.calls]
```

### 5. GREEN cycle for `validate_api_key.py`

Files to create: `src/chatbot/application/validate_api_key.py`.

Algorithm in pseudocode:

```text
CONSTANT MIN_LENGTH := 20 ; CONSTANT MAX_LENGTH := 200
FUNCTION validate_api_key(api_key):
    IF api_key KHÔNG phải str: RAISE InvalidApiKey("Khóa API phải là chuỗi ký tự")
    trimmed := api_key.strip()
    IF NOT (MIN_LENGTH <= len(trimmed) <= MAX_LENGTH): RAISE InvalidApiKey("Khóa API phải dài 20 đến 200 ký tự")
    FOR mỗi ch IN trimmed:
        IF ch.isspace(): RAISE InvalidApiKey("Khóa API không được chứa khoảng trắng bên trong")
        IF ord(ch) < 33 HOẶC ord(ch) > 126: RAISE InvalidApiKey("Khóa API chỉ được dùng ký tự ASCII in được")
```

```python
from src.chatbot.domain.errors import InvalidApiKey

MIN_LENGTH = 20
MAX_LENGTH = 200


def validate_api_key(api_key: object) -> str:
    if not isinstance(api_key, str):
        raise InvalidApiKey("Khóa API phải là chuỗi ký tự")

    if not MIN_LENGTH <= len(trimmed) <= MAX_LENGTH:

    return trimmed
```

```python
"""Use case gửi một tin và trả lời của mô hình."""
from __future__ import annotations

from src.chatbot.application.validate_message import validate_message
from src.chatbot.application.validate_session_id import validate_session_id
from src.chatbot.domain.errors import ApiKeyMissing, UpstreamError
from src.chatbot.domain.message import Message
from src.chatbot.domain.ports.api_key_store import ApiKeyStore
from src.chatbot.domain.ports.chat_model import ChatModel
from src.chatbot.domain.ports.memory_repository import MemoryRepository
from src.chatbot.domain.trim_history import trim_history

EMPTY_REPLY_MESSAGE = "Mô hình trả về nội dung rỗng"


def send_message(
    repo: MemoryRepository,
    model: ChatModel,
    store: ApiKeyStore,
    system_prompt: str,
    max_messages: int,
    session_id: str,
    text: str,
) -> str:
    sid = validate_session_id(session_id)
    msg = validate_message(text)
    if not store.is_configured():
        raise ApiKeyMissing("Chưa cấu hình khóa API, hãy nhập khóa ở hộp thoại")
    history = repo.get(sid)
    if history:
        history = trim_history(history, max_messages)
    reply = model.reply(system_prompt, history, msg)
    if not isinstance(reply, str) or not reply.strip():
        raise UpstreamError(502, EMPTY_REPLY_MESSAGE)
    reply = reply.strip()
    repo.append(sid, [Message(role="human", content=msg), Message(role="ai", content=reply)])
    return reply
```

# 4. Format:

Terms used exactly once: opencode is a programming assistant that runs in a command-line window; API is the programming interface of an external service; endpoint is the URL path of an API; venv is a virtual Python environment; pytest is a test-running tool; DDD is layered architecture by domain; TDD is the process of writing a test first and then the code; MUI is the Material component set for React; formal spec is a formal specification using the PRE, POST, INV, ERR, KILL blocks.

**PRE**
- P1, P2, P3 are done: the directory tree, `venv` is activated, `pytest.ini` has `pythonpath = .` and `testpaths = tests`, `requirements.txt` is installed, `src/chatbot/config/*` and `src/chatbot/domain/*` already have green tests.
- `py -m pytest -q` runs before this layer begins.

**POST**
- Exactly 14 files exist in scope, each file under 100 lines, each function in its own file.
- The four test files in the list run green, written before the code (TDD): the RED run has evidence in the log, the GREEN run has evidence in the log.

**INV**
- INV1: ∀ function in `application/`: import only from `chatbot.domain.*` and `chatbot.application.*`; do NOT import `flask`, `langchain`, `openai`, `dotenv`, `os`, `json`, `pathlib`.
- INV2: ∀ use case: validate input first, write memory after, do not swallow errors.
- INV3: every key used in tests matches the pattern `TEST_KEY_` + 20 x's.
- INV4: file names written in the report belong only to the B2 directory tree.

**ERR**
- `InvalidSession`, `InvalidMessage`, `InvalidApiKey`, `ApiKeyMissing` are thrown in this layer; `UpstreamError` is used only for code 502 when the model returns empty.
- Errors from `repo` or `store` propagate to the caller, are NOT re-wrapped.

**KILL**
- Stop immediately if the 100-line check command prints a file name, or if the secret scan command prints a match.

**Final report format for opencode**, in exactly this order, no other sections added:

1. File table, columns: `file` | `line count` | `covering test` | `status`. Every line count less than 100.
2. RED run block: the command `py -m pytest -q tests/test_validators.py tests/test_send_message.py tests/test_reset_conversation.py tests/test_configure_api_key.py` and the verbatim first error line.
3. GREEN run block: the same command and the result line `49 passed`.
4. The 100-line rule check command, with a confirmation line that it printed nothing.
5. Mapping table from B10 edge cases to test names, columns `case` | `test name`.

```python
# src/chatbot/application/validate_api_key.py
from src.chatbot.domain.errors import InvalidApiKey

MIN_KEY_LENGTH = 20
MAX_KEY_LENGTH = 200


def _is_printable_ascii(value: str) -> bool:
    return all(32 <= ord(char) <= 126 for char in value)


def validate_api_key(api_key: str) -> str:
    """Kiểm tra hình thức khóa, KHÔNG kiểm tiền tố nhà cung cấp."""
    if not isinstance(api_key, str):
        raise InvalidApiKey("api_key phải là chuỗi")
    value = api_key.strip()
    if not MIN_KEY_LENGTH <= len(value) <= MAX_KEY_LENGTH:
        raise InvalidApiKey(
            f"api_key phải dài {MIN_KEY_LENGTH} đến {MAX_KEY_LENGTH} ký tự"
        )
    if any(char.isspace() for char in value):
        raise InvalidApiKey("api_key không được chứa khoảng trắng bên trong")
    if not _is_printable_ascii(value):
        raise InvalidApiKey("api_key chỉ gồm ký tự ASCII in được")
    return value
```

```python
# src/chatbot/application/send_message.py
from src.chatbot.application.validate_message import validate_message
from src.chatbot.application.validate_session_id import validate_session_id
from src.chatbot.domain.errors import ApiKeyMissing, UpstreamError
from src.chatbot.domain.message import Message
from src.chatbot.domain.ports.api_key_store import ApiKeyStore
from src.chatbot.domain.ports.chat_model import ChatModel
from src.chatbot.domain.ports.memory_repository import MemoryRepository
from src.chatbot.domain.trim_history import trim_history

EMPTY_REPLY_STATUS = 502
EMPTY_REPLY_MESSAGE = "Mô hình trả lời rỗng"


def send_message(
    repo: MemoryRepository,
    model: ChatModel,
    store: ApiKeyStore,
    system_prompt: str,
    max_messages: int,
    session_id: str,
    text: str,
) -> str:
    """Thứ tự cứng: kiểm đầu vào, kiểm khóa, đọc bộ nhớ, gọi mô hình, rồi mới ghi."""
    sid = validate_session_id(session_id)
    message = validate_message(text)
    if not store.is_configured():
        raise ApiKeyMissing("Chưa có khóa API, cần nhập khóa trước")
    history = trim_history(repo.get(sid), max_messages)
    reply = model.reply(system_prompt, history, message)
    if not isinstance(reply, str) or not reply.strip():
        raise UpstreamError(EMPTY_REPLY_STATUS, EMPTY_REPLY_MESSAGE)
    repo.append(sid, [Message("human", message), Message("ai", reply)])
    return reply
```

```python
class FakeMemoryRepository:
    """Bản giả MemoryRepository ghi lại lời gọi, cho phép tiêm lỗi."""

    def __init__(self, initial=None):
        self.sessions = {
            session_id: list(items)
            for session_id, items in (initial or {}).items()
        }
        self.calls = []
        self.error = None

    def fail_with(self, error):
        self.error = error
        return self

    def get(self, session_id):
        self.calls.append(("get", session_id))
        if self.error is not None:
            raise self.error
        return list(self.sessions.get(session_id, []))

    def append(self, session_id, messages):
        self.calls.append(("append", session_id))
        if self.error is not None:
            raise self.error
        self.sessions.setdefault(session_id, []).extend(messages)

    def reset(self, session_id):
        self.calls.append(("reset", session_id))
        if self.error is not None:
            raise self.error
        self.sessions[session_id] = []

    def call_names(self):
        return [name for name, _ in self.calls]
```

# 6. Notices:

- DO NOT import `flask`, `langchain`, `openai`, `dotenv` in `application/`, because this layer must run with only domain and port.
- DO NOT read the `.env` file in `application/`, because reading the key belongs to `EnvApiKeyStore` in the infrastructure layer.
- DO NOT call `repo.append` before there is a `reply`, because a model error would leave the memory holding a hanging message.
- DO NOT swallow errors with `except Exception: pass`, because file-write errors and model errors must propagate up to the interface layer.
- DO NOT check the key after reading memory, because the test command `test_kiem_khoa_truoc_khi_doc_bo_nho` deliberately catches this wrong order.
- DO NOT return the API key from `get_setup_status`, because the key may only live in the `.env` file.
- DO NOT check the provider prefix in `validate_api_key`, because the blueprint assigns that authority to `AuthenticationError` of the external service.
- DO NOT strip whitespace in `validate_session_id`, because a session containing whitespace must be rejected.
- DO NOT create new error classes in this layer, because `UpstreamError` already exists in `domain/errors.py` written by P3.
- DO NOT cram many functions into one file, because the one-function-per-file rule is an acceptance condition.
- DO NOT let a file exceed 100 lines, because the line check command will print the file name and halt the debugging loop.
- DO NOT use `python3`, because on Windows 11 the invocation is `py`.
- DO NOT use bash commands, `curl`, `sudo`, `source`, `grep`, because the environment has only PowerShell; look up files with `Select-String` and `Get-ChildItem`.
- DO NOT write real API keys into tests, because secrets leak into source code; only use the pattern `TEST_KEY_` + 20 x's.
- DO NOT run tests that need real network, because `test_send_message.py` must be green even when the machine is offline.
- DO NOT start the server in the opencode shell, because `Start-Process` must be used until the trial run at P8.
- DO NOT write the key into `localStorage` or into the reply, because the key exists only in the `.env` file on the server side.
- DO NOT invent file names outside the B2 directory tree, for example do not create a separate configuration file for tests.
- DO NOT connect two tabs in a test, because each test builds its own fake, so state does not leak between them.
- DO NOT skip the green step after the red step, because TDD evidence is two runs of the same command.


Binding rule B24: every prompt must state how to resume if opencode stops midway. Before work begins, define a re-paste rule: if the session halts, the operator re-pastes the original prompt unchanged, then appends only the last completed step and the current failing symptom. Checkpoint progress by tests: after each milestone, run the smallest relevant test command, and record its exact output so a resumed session can verify prior work instead of redoing it. Never rely on memory of prior turns; treat the checkpoint log as the single source of truth. If tests were green at the last checkpoint, resume from the next unfinished step; if red, fix before advancing. Acceptance: a prompt satisfies B24 only if a fresh session, given the re-paste rule and the test checkpoint log alone, can continue to completion without re-executing any already-passing step.

Requirement B35 is a binding rule: any code listing exceeding 99 lines constitutes a reference design that the builder must decompose into modules of at most 99 lines each, with exactly one function per file, while updating all import statements accordingly; the original monolithic listing is never committed as a single file. Acceptance test: a 150-line reference implementation produces at least two files each ≤99 lines, each containing exactly one function, and the test suite passes with updated imports.

Binding rule on the import root (B36). Every import in every source file, test and listing uses the prefix `src.chatbot.` from the project root, for example `from src.chatbot.domain.errors import UpstreamError`. The form `from chatbot.` is forbidden. Two import names for one module create two copies of it in memory, so an `isinstance` check on an exception class fails across layers and every upstream error (401, 429, timeout, empty reply) becomes a generic HTTP 500. Acceptance: `rg -n "^\s*from chatbot\." src tests run.py` prints nothing.
