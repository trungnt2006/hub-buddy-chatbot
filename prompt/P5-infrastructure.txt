## 3b. Short glossary

- **opencode**: a programming assistant running in a command window, reading instructions in English or Vietnamese and then editing files and running commands; in this blueprint opencode is the tool that executes the specification, not a component of the chatbot.
- **API**: application programming interface, that is, the set of rules for calling and receiving data from an external service; here it is OpenAI's text-reply service.
- **endpoint**: a concrete path that the API listens on, for example `POST /api/chat`; each endpoint has one method, one request body and one return shape.
- **venv**: virtual environment, that is, a separate directory containing copies of the project's libraries so as not to mix with other libraries on the machine; here that directory is named `.venv`.
- **pytest**: the testing library for Python, run with the command `py -m pytest`, using `test_...` functions and fixture mechanisms such as `tmp_path`.
- **DDD**: domain-driven architecture, in which code is split into domain containing pure business rules, application containing use cases, infrastructure containing concrete techniques, and interface containing the user interface; the technical layers implement the interfaces declared by the domain.
- **TDD**: test-driven development discipline, that is, writing tests before writing code, with the goal that code exists only at the minimal level needed to turn tests from red to green.
- **MUI**: the UI component library for React, full name Material UI; here used via direct loading from the content-distribution server, with no code-compilation step.
- **formal spec**: a formal specification, that is, the way of writing requirements using preconditions, postconditions, invariants and decision rules, so that every proposition can be verified by a machine or by a specific command.

# BLUEPRINT v4: web chatbot, 10 prompts, DDD, TDD, MUI, first-time API key entry on the page

User lock-in 2026-10-07: the prompt IS the blueprint; an AI that reads all 10 prompts (P0 through P9) can build the chatbot; each prompt is at least 5,000 words, written in formal specification style, covering every case; the first thing to do when the chatbot runs for the first time is TO ASK FOR THE API KEY, send it to the server, the server stores it, and then it runs.

## B1. Goal and first-run flow
- Platform: Windows 11, PowerShell, Python invoked via `py`, coding assistant is opencode, responding model is `gpt-4o-mini` via the OpenAI API (external API).
- First-run flow:
  1. The learner runs `py run.py`; the server starts at `http://127.0.0.1:2610` WHEN THERE IS NO API KEY YET (must not crash).
  2. The browser opens the page; `main.js` calls `GET /api/setup/status`.
  3. It returns `{"configured": false}` ⇒ show the MUI dialog "Nhập khóa API" (password field + Save button).
  4. The learner pastes the key, clicks Save ⇒ `POST /api/setup` with `{"api_key": "<key>"}`.
  5. The server validates the key format, writes it into the `.env` file (line `OPENAI_API_KEY=`) atomically, updates the process memory, returns `{"ok": true}`; it must NEVER return the key.
  6. The page closes the dialog and shows the chat frame; chat runs immediately, no restart needed.
  7. Subsequent runs: `status` returns `{"configured": true}` ⇒ go straight to the chat frame.
- The key lives only in `.env`; not in logs, not in `memory.json`, not in responses, not in errors.

## B4. Domain
- `Message`: frozen dataclass `role: str` (only `"human"` or `"ai"`), `content: str` (non-empty). Wrong ⇒ `ValueError`.
- `trim_history(messages: list[Message], limit: int) -> list[Message]`: returns the LAST `limit` messages, preserving order; `limit <= 0` ⇒ `ValueError`; empty list ⇒ empty; fewer than `limit` ⇒ return all; does not modify the input list.
- `errors.py`: `ApiKeyMissing`, `InvalidApiKey`, `InvalidMessage`, `InvalidSession`, `UpstreamError(status: int, message: str)`; all inherit `ChatbotError(Exception)`.
- Ports (abstract classes `abc.ABC`):
  - `MemoryRepository`: `get(session_id: str) -> list[Message]`, `append(session_id: str, messages: list[Message]) -> None`, `reset(session_id: str) -> None`.
  - `ChatModel`: `reply(system_prompt: str, history: list[Message], user_text: str) -> str`.
  - `ApiKeyStore`: `is_configured() -> bool`, `get() -> str`, `save(api_key: str) -> None`.

## B5. Application (use cases, one function per file)
- `validate_session_id(session_id) -> str`: matches `^[A-Za-z0-9-]{8,64}$`, otherwise `InvalidSession`.
- `validate_message(text) -> str`: trims leading and trailing whitespace; empty ⇒ `InvalidMessage`; longer than 4000 characters ⇒ `InvalidMessage`.
- `validate_api_key(api_key) -> str`: trims whitespace; length 20 to 200; only printable ASCII characters, NO whitespace inside; wrong ⇒ `InvalidApiKey`. Do NOT check the vendor prefix.
- `get_setup_status(store) -> dict`: `{"configured": store.is_configured()}`.
- `configure_api_key(store, api_key) -> None`: `store.save(validate_api_key(api_key))`.
- `send_message(repo, model, store, system_prompt, max_messages, session_id, text) -> str`:
  1. `sid = validate_session_id(...)`, `msg = validate_message(...)`.
  2. `store.is_configured()` false ⇒ `ApiKeyMissing`.
  3. `history = trim_history(repo.get(sid), max_messages)` (if empty, skip trimming).
  4. `reply = model.reply(system_prompt, history, msg)`.
  5. `repo.append(sid, [Message("human", msg), Message("ai", reply)])` ONLY after `reply` exists; a model error ⇒ write NOTHING to memory.
  6. return `reply`.
- `reset_conversation(repo, session_id) -> None`: validate `session_id`, then `repo.reset(sid)`; resetting a non-existent session is a silent success.

## B6. Infrastructure
- `atomic_write_text(path, text)`: writes to a temp file in the same directory then `os.replace`; creates the parent directory if missing; on error ⇒ delete the temp file, rethrow the error.
- `atomic_write_json(path, data)`: `json.dumps(ensure_ascii=False, indent=2)` then `atomic_write_text`.
- `JsonMemoryRepository(path)`: uses `threading.Lock`; file format `{"<session_id>": [{"role": "human", "content": "..."}]}`; missing file ⇒ empty; corrupt file (invalid JSON) ⇒ rename to `memory.json.corrupt-<timestamp>` then start empty, MUST NOT crash; `append` reads then writes atomically within the same lock; stores ALL messages (trimming happens only when reading for the model).
- `load_system_prompt(path) -> str`: reads UTF-8; missing file ⇒ returns a short Vietnamese default, MUST NOT crash; empty file ⇒ also the default.
- `EnvApiKeyStore(env_path)`: `is_configured()` is true exactly when `get()` is non-empty; `get()` reads `OPENAI_API_KEY` from the `.env` file (and from `os.environ` if the file is missing); `save(key)` rewrites the `.env` file keeping the other lines intact, replacing or appending exactly one line `OPENAI_API_KEY=<key>`, writes atomically, updates `os.environ`; write error ⇒ rethrow, MUST NOT leave a half-written file.
- `mask_secret(value) -> str`: returns `"****"` plus the last 4 characters when the length is 12 or more; otherwise `"****"`; used for logs, MUST NEVER write the real key.
- `LangChainChatModel(settings, store)`: each `reply` builds `ChatPromptTemplate.from_messages([("system", system_prompt), MessagesPlaceholder("history"), ("human", "{input}")])`, attaches `ChatOpenAI(model=settings.openai_model, temperature=settings.openai_temperature, timeout=settings.openai_timeout, api_key=store.get())`, converts `Message` to `HumanMessage`/`AIMessage`, returns `.content`; OpenAI error ⇒ `UpstreamError(*map_openai_error(exc))`; the key is read AGAIN on every turn so that no restart is needed after `/api/setup`.
- `map_openai_error(exc) -> tuple[int, str]`: `AuthenticationError`→401 "Khóa API không đúng, nhập lại"; `RateLimitError` (HTTP 429)→503 "Hệ thống đang quá tải, thử lại sau"; `APITimeoutError`→504 "Mô hình trả lời quá lâu"; `APIConnectionError`→502 "Không kết nối được dịch vụ mô hình"; otherwise→500 "Có lỗi không mong đợi".

4. Create `infrastructure/atomic_write_text.py`. Signature `atomic_write_text(path: Path, text: str) -> None`. Import list: `os`, `from pathlib import Path`. Pseudocode algorithm, one step per line:

- B1: `duong_dan := Path(path)`, `thu_muc_cha := duong_dan.parent`.
- B2: IF `thu_muc_cha` does not exist yet THEN call `mkdir(parents=True, exist_ok=True)`.
- B3: `tam := thu_muc_cha / (duong_dan.name + ".tmp")`, i.e. the temp file in the SAME DIRECTORY as the target file, because a different directory means `os.replace` does not guarantee the same disk and atomicity is lost.
- B4: TRY open `tam` with `encoding="utf-8"` and `newline="\n"`, write `text`, close the file.
- B5: `os.replace(tam, duong_dan)`.
- B6: CATCH every `Exception` as `e`: IF `tam` exists THEN delete with `missing_ok=True`; RAISE `e` again with a bare `raise` to preserve the traceback.
- B7: RETURN nothing.

```python
import os
from pathlib import Path


def atomic_write_text(path: Path, text: str) -> None:
    duong_dan = Path(path)
    thu_muc_cha = duong_dan.parent
    if not thu_muc_cha.exists():
        thu_muc_cha.mkdir(parents=True, exist_ok=True)
    tam = thu_muc_cha / (duong_dan.name + ".tmp")
    try:
        with tam.open("w", encoding="utf-8", newline="\n") as tep:
            tep.write(text)
        os.replace(tam, duong_dan)
    except Exception:
        tam.unlink(missing_ok=True)
        raise
```

```python
def map_openai_error(exc: Exception) -> tuple[int, str]:
    ma = getattr(exc, "status_code", None)
    if ma is None:
        ma = getattr(getattr(exc, "response", None), "status_code", None)
    ten_lop = [k.__name__ for k in type(exc).__mro__]
    if "AuthenticationError" in ten_lop or ma == 401:
```

## 3d. Decision tables

Table D1. `atomic_write_text` and `atomic_write_json`.

| Input condition | Output result | Error code or exception |
|---|---|---|
| Parent directory does not exist | Create the parent directory then write | none |
| Target file does not exist | Create it via a temp file then `os.replace` | none |
| `os.replace` fails | Delete the temp file, the old file stays intact | re-raise the original `OSError` |
| Temp file write fails midway | Delete the half-written temp file, the old file stays intact | re-raise the original `OSError` |
| Data contains Vietnamese, emoji, `<script>` tags | Write real UTF-8, no `\uXXXX` | none |
| File open on Windows | Write `newline="\n"`, no CRLF generated | none |
| `atomic_write_json` receives a dict or list | `indent=2`, `ensure_ascii=False`, key order preserved | none |

Table D2. `JsonMemoryRepository`.

| Input condition | Output result | Error code or exception |
|---|---|---|
| `memory.json` does not exist | `get` returns `[]` | none |
| Malformed JSON | Rename to `memory.json.corrupt-<timestamp>`, start empty | none, only writes a warning with the key masked |
| File empty in bytes | Treat as empty, do NOT rename | none |
| Valid JSON but not an object at the top level | Treat as empty | none |
| A record has a wrong `role` or empty `content` | Skip exactly that record, keep valid records | none |
| `append` for a new session | Create a new branch in the object | none |
| `append` with a history of 12 messages | Store all 12 messages, do NOT truncate | none |
| `reset` for a session not present | Do not write the file | none |
| Twenty threads writing concurrently to the same session | All twenty messages present, none lost, none duplicated | none |
| The directory containing `memory.json` does not exist | Create the directory then write | none |
| A message with accented Vietnamese and special characters | Stored verbatim as a string | none |
| An API key inside message content | Still stored verbatim, but no system key is written along with it | none |

Table D3. `EnvApiKeyStore`.

| Input condition | Output result | Error code or exception |
|---|---|---|
| `.env` file missing, `os.environ` has the key | `get` returns the key from `os.environ` | none |
| `.env` file missing, `os.environ` has nothing either | `get` returns `""`, `is_configured` is `False` | none |
| Line ends with CRLF | Drop the `\r`, read the correct value | none |
| Multiple `OPENAI_API_KEY` lines when reading | The LAST line wins | none |
| Value wrapped in double quotes | Quotes peeled off | none |
| Whitespace around the equals sign | The key is still recognized | none |
| `save` when the file does not exist yet | Create the file with exactly one key line | none |
| `save` when a key line already exists | Replace in place, keep the order of other lines | none |
| `save` when there are multiple key lines | Exactly one key line remains | none |
| After `save` | `os.environ` updated, chatting works immediately | none |
| Write permission denied | Old file stays intact, no leftover temp file, `os.environ` unchanged | re-raise `PermissionError` |
| `save` receives an empty string or whitespace | NOT accepted at this layer, blocked earlier in `validate_api_key` | `InvalidApiKey` |

Table D4. `map_openai_error` and `load_system_prompt`.

| Input condition | Output result | Error code or exception |
|---|---|---|
| `AuthenticationError` or code 401 | `(401, "Khóa API không đúng, nhập lại")` | none |
| `RateLimitError` or code 429 | `(503, "Hệ thống đang quá tải, thử lại sau")` | none |
| Class name contains `Timeout` | `(504, "Mô hình trả lời quá lâu")` | none |
| Class name contains `Connection` | `(502, "Không kết nối được dịch vụ mô hình")` | none |
| A strange subclass of `APIStatusError`, e.g. 500 | `(500, "Có lỗi không mong đợi")` | none |
| Exception not belonging to the `openai` package | `(500, "Có lỗi không mong đợi")` | none |
| Exception carries `api_key` as an attribute | The message does NOT contain the key | none |
| `system-prompt.txt` missing, empty, or whitespace only | Default Vietnamese string with diacritics | none |
| `system-prompt.txt` unreadable | Default string | none, error swallowed |

Table D5. `LangChainChatModel.reply`.

| Input condition | Output result | Error code or exception |
|---|---|---|
| Empty key in the store | Stop before calling the model | `ApiKeyMissing` |
| Key just saved on the previous turn | This turn uses the new key, no restart needed | none |
| History mixing `human` and `ai` | Converted to `HumanMessage` and `AIMessage`, order preserved | none |
| Empty history | The prompt template only has the system message and the user message | none |
| Two consecutive calls | Each turn has its own model object, no reuse | none |
| Model returns empty content or all whitespace | Reports an empty-reply error | `UpstreamError(502, "empty_reply")` |
| Model raises an existing `UpstreamError` | Re-raised unchanged, not wrapped twice | `UpstreamError` |
| Model raises a different error | Apply `map_openai_error` then wrap | `UpstreamError` |

Table D6. Invariant rules about keys in P5.

| Rule | Decision | Reason |
|---|---|---|
| When to read the key | Every `reply` turn, read from the store once | no server restart needed after `/api/setup` |
| When to write the key | Only inside `save`, and only after `os.replace` returns | never let the process pretend it already has the key |
| When it may be logged | Only via `mask_secret`, at most eight characters | no key leakage into the log file |
| When to validate formally | In P4's `validate_api_key`, not here | exactly one place is responsible |
| When to show the key back to the browser | Never, not even on error | the P6 route returns only the code and the constant message |
| Keys in `memory.json` | Never | the memory file only holds roles and message content |

## ERR. Error matrix for P5

**ERR.1. Message loss when twenty threads write concurrently.** Symptom: `test_hai_muoi_luong_ghi_dong_thoi_khong_mat_tin` is red, the number of messages received is less than twenty. Cause: `append` reads the file then writes without holding a lock that wraps both operations. Fix: wrap both read and write in a `threading.Lock`, each instance holding its own lock object. File involved: `infrastructure/json_memory_repository.py`.

**ERR.2. Leftover temp file when an error occurs midway.** Symptom: after `os.replace` fails, the directory gains an extra file ending in `.tmp`. Cause: no cleanup branch inside `except`. Fix: delete the temp file with `missing_ok=True` then re-raise the original error with a bare `raise`, not `raise ... from None`, to preserve the traceback. File involved: `infrastructure/atomic_write_text.py`.

**ERR.3. A broken `memory.json` crashes the server.** Symptom: `get` raises `JSONDecodeError` up to the route. Cause: the reading function does not catch errors. Fix: catch `JSONDecodeError` and `UnicodeDecodeError`, rename the broken file with a timestamp, then start empty. File involved: `infrastructure/json_memory_repository.py`.

**ERR.4. Vietnamese and emoji corrupted in the file.** Symptom: the file contains `\uXXXX` strings instead of real characters, or it cannot be opened on re-read. Cause: `json.dumps` missing `ensure_ascii=False`, or the file opened without declaring `encoding="utf-8"`. Fix: pin both points in `atomic_write_json.py` and `atomic_write_text.py`, verified by a Unicode test. Files involved: `infrastructure/atomic_write_json.py`, `infrastructure/atomic_write_text.py`.

**ERR.5. `.env` using CRLF corrupts the key.** Symptom: `get` returns a value with a `\r` character; `is_configured` is still correct but the key sent to the service is wrong and gets rejected. Cause: the `\r` is not dropped after splitting lines. Fix: always use `splitlines()` then `strip()` each line. File involved: `infrastructure/env_api_key_store.py`.

**ERR.6. Multiple `OPENAI_API_KEY` lines in `.env`.** Symptom: each chat turn uses the old key, the user thinks it was saved but it has no effect. Cause: taking the first key line. Fix: the read rule is last line wins, the write rule is exactly one key line remains. File involved: `infrastructure/env_api_key_store.py`.

**ERR.7. `.env` does not exist when the key needs saving.** Symptom: `save` raises `FileNotFoundError` on the very first turn of the B1 first-run path. Cause: assuming the file already exists. Fix: treat the content as empty then write anew; `atomic_write_text` already creates the parent directory. Files involved: `infrastructure/env_api_key_store.py`, `infrastructure/atomic_write_text.py`.

**ERR.8. Writing `.env` denied by permissions.** Symptom: `PermissionError` midway; handled wrongly it leaves a half-done file and the old key is lost. Cause: writing directly into the target file. Fix: write only through `atomic_write_text`, re-raise the original error, let the P6 route turn it into 500 `save_failed`. Files involved: `infrastructure/env_api_key_store.py`, `infrastructure/atomic_write_text.py`.

**ERR.9. `os.environ` updated before the write finishes.** Symptom: the write fails but the process still pretends it has the key, the next chat turn falls into an error loop. Cause: assigning `os.environ` at the top of the function. Fix: place the `os.environ` assignment as the last step, after `os.replace` returns. File involved: `infrastructure/env_api_key_store.py`.

**ERR.10. The key is read once and reused forever.** Symptom: after saving a new key via `POST /api/setup`, the user must stop and start the server again before chatting, violating B1 step 6. Cause: building `ChatOpenAI` once inside `__init__`. Fix: build `ChatOpenAI` and call `store.get()` inside `reply` on every turn. File involved: `infrastructure/langchain_chat_model.py`.

**ERR.11. A missing `system-prompt.txt` crashes the server at startup.** Symptom: `run.py` stops with `FileNotFoundError`, the browser cannot open the page. Cause: reading the file without catching errors. Fix: swallow `OSError` and `UnicodeDecodeError`, return the default string. File involved: `infrastructure/load_system_prompt.py`.

**ERR.12. `system-prompt.txt` is empty or whitespace only.** Symptom: the model rambles because there is no system role. Cause: returning empty content. Fix: `strip()` then check for emptiness, and if empty return the default Vietnamese string with diacritics. File involved: `infrastructure/load_system_prompt.py`.

**ERR.13. The key leaks into an error message.** Symptom: a log or response contains the beginning of the key. Cause: concatenating `str(exc)` of an authentication error into the message. Fix: `map_openai_error` returns only Vietnamese constants, every log path uses `mask_secret`. Files involved: `infrastructure/map_openai_error.py`, `infrastructure/mask_secret.py`.

**ERR.14. The fake `ChatOpenAI` is not used.** Symptom: a test calls the real service or reports a missing key. Cause: `monkeypatch` is attached to the `langchain_openai` package while the code imports directly from P5's own module. Fix: import the module `chatbot.infrastructure.langchain_chat_model` then `monkeypatch.setattr(lc, "ChatOpenAI", _tao_ban_gia)`. Files involved: `tests/test_langchain_chat_model.py`, `infrastructure/langchain_chat_model.py`.

**ERR.15. A mid-run network loss is classified as 500.** Symptom: the user sees a generic notice instead of a retry hint. Cause: the connection error class is not recognized. Fix: check whether a class name in the MRO contains `Connection` and then return 502. File involved: `infrastructure/map_openai_error.py`.

**ERR.16. Reversed check order turns timeouts into connection loss.** Symptom: `APITimeoutError` is classified as 502 because `APITimeoutError` inherits `APIConnectionError`, or 429 is classified as 401. Cause: the `Connection` branch is evaluated before the `Timeout` branch. Fix: keep the exact order authentication, overload, timeout, connection, and only then the remaining branch. File involved: `infrastructure/map_openai_error.py`.

**ERR.17. Double wrapping loses the correct code.** Symptom: every error bubbling up becomes 500. Cause: `except UpstreamError` is missing, so an already-classified error is re-classified by `map_openai_error`. Fix: catch `UpstreamError` first and re-raise it unchanged. File involved: `infrastructure/langchain_chat_model.py`.

**ERR.18. Wrong message order sent to the model.** Symptom: `test_reply_dung_thu_tu_tin_va_kieu_tin` is red because the user message sits before the system message, or an old reply message is sent as a user message. Cause: building the prompt template in the wrong order `system`, `history`, `human`, or converting `Message` to `HumanMessage` for both roles. Fix: keep the `ChatPromptTemplate` frame at R3 and branch on `role` at R5, verified by both a content comparison and a message-type comparison. File involved: `infrastructure/langchain_chat_model.py`.

**ERR.19. An empty model reply is written into memory.** Symptom: the history contains an empty reply message, and the next turn sends a meaningless message to the model. Cause: `reply` returns an empty string instead of raising. Fix: check for emptiness at R10 and raise `UpstreamError(502, "empty_reply")` before the P4 use case can write it into memory. File involved: `infrastructure/langchain_chat_model.py`.

**ERR.20. Tests flicker red because the multithreaded measurement does not block.** Symptom: `py -m pytest -q` gives different results across two consecutive runs. Cause: threads have not been `join`ed before asserting, or the lock was created at class level so different instances still collide. Fix: `join` all twenty threads before reading, and keep the lock at instance level. Files involved: `tests/test_json_memory_repository.py`, `infrastructure/json_memory_repository.py`.

**ERR.21. A broken file is renamed over an older broken file.** Symptom: the timestamp only has second precision, so two breaks in the same second overwrite each other. Cause: `time.time()` rounded into an integer string. Fix: use a timestamp with a millisecond-fraction component or add a counting suffix, and rename only when the broken target file still exists. File involved: `infrastructure/json_memory_repository.py`.

**ERR.22. Writing a file on Windows generates CRLF and then locks itself out.** Symptom: right after saving, `.env` is read by `load_settings` with extra characters and raises `SettingsError`. Cause: the file was opened without declaring `newline="\n"`. Fix: pin `newline="\n"` inside `atomic_write_text`, verified with `splitlines()` in `EnvApiKeyStore`. Files involved: `infrastructure/atomic_write_text.py`, `infrastructure/env_api_key_store.py`.

Decision table for `_doc` of `JsonMemoryRepository`:

| condition | action | returns |
|---|---|---|
| file does not exist | do not write junk files | `{}` |
| file is invalid JSON, or a UTF-8 decoding error, or a read error | rename to `memory.json.corrupt-<timestamp>` then treat as new | `{}` |
| file is valid JSON but not an object | rename as above | `{}` |
| file is valid JSON and is an object | keep it as is | the parsed object |

ERR: every system error is re-raised intact, never swallowed; only `map_openai_error` translates OpenAI errors into `UpstreamError`; if `reply` returns an empty string, raise `UpstreamError(502, ...)`.

KILL: stop immediately if any file exceeds 99 lines; stop if `py -m pytest -q` reports a collection error; stop if the secret-scan command prints any line; stop if `python3`, `curl`, `sudo`, `source` or `grep` has to be used; stop if a function is placed in the same file as another function from a different tier.

```python
import os
import tempfile
from pathlib import Path


def atomic_write_text(path, text):
    """Ghi văn bản theo kiểu nguyên tử: ghi tệp tạm cùng thư mục rồi os.replace."""
    dich = Path(path)
    dich.parent.mkdir(parents=True, exist_ok=True)
    mo_ta, ten_tam = tempfile.mkstemp(prefix=dich.name + ".tmp-", dir=str(dich.parent))
    duong_dan_tam = Path(ten_tam)
    try:
        with os.fdopen(mo_ta, "w", encoding="utf-8", newline="") as tep:
            tep.write(text)
            tep.flush()
            os.fsync(tep.fileno())
        os.replace(duong_dan_tam, dich)
    except BaseException:
        duong_dan_tam.unlink(missing_ok=True)
        raise
    return str(dich)
```

```python
import json
import threading
import time
from pathlib import Path

from ..domain.message import Message
from ..domain.ports.memory_repository import MemoryRepository
from .atomic_write_json import atomic_write_json


class JsonMemoryRepository(MemoryRepository):
    """Kho lịch sử hội thoại trong tệp JSON, mọi thao tác nằm sau khóa luồng."""

    def __init__(self, path):
        self._path = Path(path)
        self._lock = threading.Lock()

    def get(self, session_id):
        with self._lock:
            du_lieu = self._doc()
        tin = []
        for muc in du_lieu.get(session_id, []):
            try:
                tin.append(Message(muc["role"], muc["content"]))
            except (KeyError, TypeError, ValueError):
                continue
        return tin

    def append(self, session_id, messages):
        moi = [{"role": m.role, "content": m.content} for m in messages]
        with self._lock:
            du_lieu = self._doc()
            du_lieu.setdefault(session_id, []).extend(moi)
            atomic_write_json(self._path, du_lieu)

    def reset(self, session_id):
        with self._lock:
            du_lieu = self._doc()
            if session_id not in du_lieu:
                return
            del du_lieu[session_id]
            atomic_write_json(self._path, du_lieu)

    def _doc(self):
        if not self._path.exists():
            return {}
        try:
            du_lieu = json.loads(self._path.read_text(encoding="utf-8-sig"))
        except (json.JSONDecodeError, UnicodeDecodeError, OSError):
            du_lieu = None
        if isinstance(du_lieu, dict):
            return du_lieu
        self._cach_ly()
        return {}

    def _cach_ly(self):
        ten = self._path.name + ".corrupt-" + str(int(time.time()))
        try:
            self._path.replace(self._path.with_name(ten))
        except OSError:
            pass
```

```python
import os
from pathlib import Path

from ..domain.ports.api_key_store import ApiKeyStore
from .atomic_write_text import atomic_write_text

TEN_KHOA = "OPENAI_API_KEY"


class EnvApiKeyStore(ApiKeyStore):
    """Đọc và ghi khóa API trong tệp .env bằng ghi nguyên tử."""

    def __init__(self, env_path):
        self._path = Path(env_path)

    def is_configured(self):
        return bool(self.get())

    def get(self):
        if not self._path.exists():
            return os.environ.get(TEN_KHOA, "")
        for dong in self._doc().splitlines():
            if self._la_dong_khoa(dong):
                return dong.strip().split("=", 1)[1].strip()
        return ""

    def save(self, api_key):
        dong_cu = self._doc().splitlines() if self._path.exists() else []
        vi_tri = next((i for i, d in enumerate(dong_cu) if self._la_dong_khoa(d)), None)
        giu_lai = [d for d in dong_cu if not self._la_dong_khoa(d)]
        giu_lai.insert(len(giu_lai) if vi_tri is None else vi_tri, TEN_KHOA + "=" + api_key)
        atomic_write_text(self._path, "\n".join(giu_lai) + "\n")
        os.environ[TEN_KHOA] = api_key

    def _doc(self):
        try:
            return self._path.read_text(encoding="utf-8-sig")
        except (OSError, UnicodeDecodeError):
            return ""

    def _la_dong_khoa(self, dong):
        return dong.strip().startswith(TEN_KHOA + "=")
```

```python
import openai

THONG_DIEP = {
    401: "Khóa API không đúng, nhập lại.",
    503: "Hệ thống đang quá tải, thử lại sau.",
    504: "Mô hình trả lời quá lâu.",
    502: "Không kết nối được dịch vụ mô hình.",
    500: "Có lỗi không mong đợi.",
}


def map_openai_error(exc):
    """Dịch lỗi OpenAI thành cặp (mã trạng thái, thông điệp tiếng Việt)."""
    if isinstance(exc, openai.AuthenticationError):
        ma = 401
    elif isinstance(exc, openai.RateLimitError):
        ma = 503
    elif isinstance(exc, openai.APITimeoutError):
        ma = 504
    elif isinstance(exc, openai.APIConnectionError):
        ma = 502
    else:
        ma = 500
    return ma, THONG_DIEP[ma]
```

```python
from langchain_core.messages import AIMessage, HumanMessage
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_openai import ChatOpenAI

from ..domain.errors import UpstreamError
from ..domain.ports.chat_model import ChatModel
from .map_openai_error import map_openai_error

LOI_RONG = "Mô hình trả về câu trả lời rỗng."


class LangChainChatModel(ChatModel):
    """Cầu nối tới mô hình trả lời, đọc khóa API ở mỗi lượt gọi."""

    def __init__(self, settings, store):
        self._settings = settings
        self._store = store

    def reply(self, system_prompt, history, user_text):
        mau = ChatPromptTemplate.from_messages([
            ("system", system_prompt),
            MessagesPlaceholder("history"),
            ("human", "{input}"),
        ])
        mo_hinh = ChatOpenAI(
            model=self._settings.openai_model,
            temperature=self._settings.openai_temperature,
            timeout=self._settings.openai_timeout,
            api_key=self._store.get(),
        )
        try:
            ket_qua = mo_hinh.invoke(mau.invoke({
                "history": self._doi_doi(history),
                "input": user_text,
            }))
        except Exception as loi:
            ma, thong_diep = map_openai_error(loi)
            raise UpstreamError(ma, thong_diep) from loi
        noi_dung = (ket_qua.content or "").strip()
        if not noi_dung:
            raise UpstreamError(502, LOI_RONG)
        return noi_dung

    def _doi_doi(self, history):
        doi = []
        for tin in history:
            if tin.role == "human":
                doi.append(HumanMessage(content=tin.content))
            else:
                doi.append(AIMessage(content=tin.content))
        return doi
```

# 6. Notices:

1. Do not embed real keys in code or tests; test keys only use `TEST_KEY_` plus 20 x characters; the reason: a real key leaking into source code is an irreversible security incident.
2. Do not write keys to logs, `memory.json`, HTTP responses or error messages; when logging is needed use `mask_secret`; the reason: keys must live only in `.env`.
3. Do not print the key value on `SettingsError` or `PermissionError`; the reason: error messages are also a leak channel.
4. Do not skip the temp file in the same directory; `os.replace` is atomic only when the temp file is on the same file system; the reason: a temp file in a different directory loses atomicity.
5. Do not open files in direct write mode for `.env` or `memory.json`; the reason: a power cut halfway through would leave a half-written file.
6. Do not use a module-level lock for the memory repository; must use the `threading.Lock` of exactly one repository; the reason: 20 threads writing concurrently will lose messages if the lock is shared.
7. Do not use `chmod` as a mandatory step; the reason: Windows has no Unix-style permission concept.
8. Do not skip `newline=""` when writing text; the reason: on Windows it would generate CRLF and break the test `test_crlf_duoc_chuan_hoa_ve_lf_khi_ghi`.
9. Do not use default `json.dumps`; must have `ensure_ascii=False`; the reason: Vietnamese with diacritics would become hard-to-read `\u` strings.
10. Do not delete a corrupt `memory.json`; must rename it with the suffix `.corrupt-<timestamp>`; the reason: deleting destroys the evidence for re-diagnosis.
11. Do not crash the application when `memory.json` is corrupt or `system-prompt.txt` is missing; the reason: the first-time flow must be able to open the key input box.
12. Do not build `ChatOpenAI` once in `__init__`; the reason: after `POST /api/setup` the user must be able to chat immediately without restarting the server.
13. Do not use `except: pass` in `reply`; must raise `UpstreamError` with a code and a Vietnamese message; the reason: the route needs the correct status code to display the notification.
14. Do not return an English message to the user in this tier; the reason: consistent Vietnamese with diacritics at every tier.
15. Do not add dependencies on `..application`, `..interface` or `..config`; the reason: the dependency arrows of layered architecture.
16. Do not put two public functions into one file within the same tier and do not duplicate a name with another file; the reason: the one-function-per-file rule at B2.
17. Do not create `.js` files or `index.html` in P5; the reason: the interface belongs to P7.
18. Do not overwrite the user's real `.env` file with sample content; the reason: it would erase the saved key.
19. Do not hard-code the model service address into the code and do not delete the `OPENAI_BASE_URL` variable; the reason: the automatic checker points it at a fake server.
20. Do not check the provider prefix in `env_api_key_store`; that belongs to `validate_api_key` of P4; the reason: avoid duplicated responsibility between the two tiers.
21. Do not use real environment variables in tests; use `monkeypatch.setenv` and `monkeypatch.delenv`; the reason: avoid polluting the student's machine.
22. Do not use wall-clock time as an assertion condition in tests; the reason: assertions based on wall-clock time are flaky under machine load.
23. Do not use bash commands and do not run the server directly in the shell of opencode; use `Start-Process` then `Start-Sleep -Seconds 3`; the reason: the environment is Windows 11 with PowerShell.
24. Do not let a file exceed 99 lines and do not skip the line-compliance check; the reason: the rule at B2 is an acceptance condition at P9.
25. Do not write `innerHTML` or `dangerouslySetInnerHTML` at any tier; the reason: user messages must be displayed verbatim, without executing code.
