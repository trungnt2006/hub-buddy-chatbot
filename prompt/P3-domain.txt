## 3b. Short glossary

- **opencode**: a coding assistant running in a command-line window, reading a long prompt then producing files and running test commands on Windows 11.
- **API**: application programming interface, here an external service that answers with text, not running on the learner's machine.
- **endpoint**: a specific path on the server that a browser or another program calls over HTTP, for example `/api/setup/status`.
- **venv**: a Python virtual environment created with `py -m venv .venv`, isolating the project libraries from system libraries, activated with `.\.venv\Scripts\Activate.ps1`.
- **pytest**: the automatic test-running tool for Python, the command used in this project is `py -m pytest -q`, the configuration file is `pytest.ini`.
- **DDD**: domain-driven design, a method that separates business rules into the core `domain/` layer and lets higher layers plug in through `ports/` contracts.
- **TDD**: the method of writing tests first, minimal code later, and re-running to keep a continuously green state.
- **MUI**: the Material user interface library for React, here loaded from CDN and using `React.createElement` instead of JSX syntax.
- **formal spec**: a way of writing formal specifications made of PRE, POST, INV, ERR, KILL blocks and numbered steps, such that every condition is checkable by a command or by a test.
- **port**: an abstract class in the domain naming the function signatures that the infrastructure layer must install, with no executable body yet.
- **pure function**: a function that gives the same output for the same input and never touches external state such as files, network, or time.
- **frozen dataclass**: an auto-generated data class with the `frozen=True` flag, reassigning a field after initialization raises an error.
- **first-run**: the first launch of the application on the learner's machine, when `.env` holds no key yet, so the key must be asked for before chatting.
- **invariant (INV)**: a statement always true no matter who calls, written to be checkable by a test or a command, not relying on spoken convention.

## B1. Goal and first-run flow
- Platform: Windows 11, PowerShell, Python invoked via `py`, coding assistant is opencode, responding model is `gpt-4o-mini` via the OpenAI API (external API).

  2. The browser opens the page; `main.js` calls `GET /api/setup/status`.

  4. The learner pastes the key, clicks Save ⇒ `POST /api/setup` with `{"api_key": "<key>"}`.
  5. The server validates the key format, writes it into the `.env` file (line `OPENAI_API_KEY=`) atomically, updates the process memory, returns `{"ok": true}`; it must NEVER return the key.
  6. The page closes the dialog and shows the chat frame; chat runs immediately, no restart needed.
  7. Subsequent runs: `status` returns `{"configured": true}` ⇒ go straight to the chat frame.
- The key lives only in `.env`; not in logs, not in `memory.json`, not in responses, not in errors.

## B4. Domain
- `Message`: frozen dataclass `role: str` (only `"human"` or `"ai"`), `content: str` (non-empty). Wrong ⇒ `ValueError`.
- `trim_history(messages: list[Message], limit: int) -> list[Message]`: returns the LAST `limit` messages, preserving order; `limit <= 0` ⇒ `ValueError`; empty list ⇒ empty; fewer than `limit` ⇒ return all; does not modify the input list.
- `errors.py`: `ApiKeyMissing`, `InvalidApiKey`, `InvalidMessage`, `InvalidSession`, `UpstreamError(status: int, message: str)`; all inherit `ChatbotError(Exception)`.
- Ports (abstract classes `abc.ABC`):
  - `MemoryRepository`: `get(session_id: str) -> list[Message]`, `append(session_id: str, messages: list[Message]) -> None`, `reset(session_id: str) -> None`.
  - `ChatModel`: `reply(system_prompt: str, history: list[Message], user_text: str) -> str`.
  - `ApiKeyStore`: `is_configured() -> bool`, `get() -> str`, `save(api_key: str) -> None`.

## B5. Application (use cases, one function per file)
- `validate_session_id(session_id) -> str`: matches `^[A-Za-z0-9-]{8,64}$`, otherwise `InvalidSession`.
- `validate_message(text) -> str`: trims leading and trailing whitespace; empty ⇒ `InvalidMessage`; longer than 4000 characters ⇒ `InvalidMessage`.
- `validate_api_key(api_key) -> str`: trims whitespace; length 20 to 200; only printable ASCII characters, NO whitespace inside; wrong ⇒ `InvalidApiKey`. Do NOT check the vendor prefix.
- `get_setup_status(store) -> dict`: `{"configured": store.is_configured()}`.
- `configure_api_key(store, api_key) -> None`: `store.save(validate_api_key(api_key))`.
- `send_message(repo, model, store, system_prompt, max_messages, session_id, text) -> str`:
  1. `sid = validate_session_id(...)`, `msg = validate_message(...)`.
  2. `store.is_configured()` false ⇒ `ApiKeyMissing`.
  3. `history = trim_history(repo.get(sid), max_messages)` (if empty, skip trimming).
  4. `reply = model.reply(system_prompt, history, msg)`.
  5. `repo.append(sid, [Message("human", msg), Message("ai", reply)])` ONLY after `reply` exists; a model error ⇒ write NOTHING to memory.
  6. return `reply`.
- `reset_conversation(repo, session_id) -> None`: validate `session_id`, then `repo.reset(sid)`; resetting a non-existent session is a silent success.

## B6. Infrastructure
- `atomic_write_text(path, text)`: writes to a temp file in the same directory then `os.replace`; creates the parent directory if missing; on error ⇒ delete the temp file, rethrow the error.
- `atomic_write_json(path, data)`: `json.dumps(ensure_ascii=False, indent=2)` then `atomic_write_text`.
- `JsonMemoryRepository(path)`: uses `threading.Lock`; file format `{"<session_id>": [{"role": "human", "content": "..."}]}`; missing file ⇒ empty; corrupt file (invalid JSON) ⇒ rename to `memory.json.corrupt-<timestamp>` then start empty, MUST NOT crash; `append` reads then writes atomically within the same lock; stores ALL messages (trimming happens only when reading for the model).
- `load_system_prompt(path) -> str`: reads UTF-8; missing file ⇒ returns a short Vietnamese default, MUST NOT crash; empty file ⇒ also the default.
- `EnvApiKeyStore(env_path)`: `is_configured()` is true exactly when `get()` is non-empty; `get()` reads `OPENAI_API_KEY` from the `.env` file (and from `os.environ` if the file is missing); `save(key)` rewrites the `.env` file keeping the other lines intact, replacing or appending exactly one line `OPENAI_API_KEY=<key>`, writes atomically, updates `os.environ`; write error ⇒ rethrow, MUST NOT leave a half-written file.
- `mask_secret(value) -> str`: returns `"****"` plus the last 4 characters when the length is 12 or more; otherwise `"****"`; used for logs, MUST NEVER write the real key.
- `LangChainChatModel(settings, store)`: each `reply` builds `ChatPromptTemplate.from_messages([("system", system_prompt), MessagesPlaceholder("history"), ("human", "{input}")])`, attaches `ChatOpenAI(model=settings.openai_model, temperature=settings.openai_temperature, timeout=settings.openai_timeout, api_key=store.get())`, converts `Message` to `HumanMessage`/`AIMessage`, returns `.content`; OpenAI error ⇒ `UpstreamError(*map_openai_error(exc))`; the key is read AGAIN on every turn so that no restart is needed after `/api/setup`.
- `map_openai_error(exc) -> tuple[int, str]`: `AuthenticationError`→401 "Khóa API không đúng, nhập lại"; `RateLimitError` (HTTP 429)→503 "Hệ thống đang quá tải, thử lại sau"; `APITimeoutError`→504 "Mô hình trả lời quá lâu"; `APIConnectionError`→502 "Không kết nối được dịch vụ mô hình"; otherwise→500 "Có lỗi không mong đợi".

1. Files to create: `src/chatbot/domain/trim_history.py`. Signature `trim_history(messages: list[Message], limit: int) -> list[Message]`.
2. Import `Message` by relative path within the same package, and use it for the type annotation.
3. Pseudocode:
```
HÀM trim_history(messages, limit):
    NẾU limit KHÔNG phải int HOẶC là bool: raise ValueError
    NẾU limit <= 0: raise ValueError
    NẾU len(messages) == 0: TRẢ về []
    NẾU len(messages) <= limit: TRẢ về list(messages)
    TRẢ về list(messages[len(messages) - limit:])
```
4. Why `bool` is blocked: in Python the `bool` class is a subclass of `int`, so `trim_history(x, True)` would trim down to one message if it were not blocked. This is an edge case because the configuration is read from an environment variable.
5. Why `len(messages) == limit` returns the whole list: B5 specifies that fewer than or equal to `limit` returns everything; the equal case must not be trimmed short.
6. PowerShell check command: `py -m pytest -q tests/test_trim_history.py`
7. Expected result: `13 passed`. `test_trim_theo_so_luong` alone contributes five runs thanks to parametrization.

```python
from .message import Message


def trim_history(messages: list[Message], limit: int) -> list[Message]:
    """Trả về `limit` tin CUỐI, giữ nguyên thứ tự, không sửa danh sách vào."""
    if not isinstance(limit, int) or isinstance(limit, bool):
        raise ValueError("limit phải là số nguyên")
    if limit <= 0:
        raise ValueError("limit phải lớn hơn 0")
    if len(messages) == 0:
        return []
    if len(messages) <= limit:
        return list(messages)
    return list(messages[len(messages) - limit:])
```

```python
import abc

from ..message import Message


class MemoryRepository(abc.ABC):
    """Cổng lưu lịch sử trò chuyện theo session_id."""

    @abc.abstractmethod
    def get(self, session_id: str) -> list[Message]:
```

## 4.2. Domain contract and decision table

`Message`:
- PRE: `role` is a `str` in `ALLOWED_ROLES`; `content` is a `str` that is non-empty after trimming whitespace.
- POST: a `frozen`, `eq=True` object with the two fields `role` and `content`.
- INV: every created `Message` is immutable; assigning an attribute again throws `dataclasses.FrozenInstanceError`.
- ERR: a wrong-typed `role`, an unknown role, a wrong-typed `content`, or content that is only whitespace all throw `ValueError`.
- KILL: do NOT trim `content` whitespace yourself, because trimming belongs to `validate_message` in the application layer.

`trim_history(messages, limit)`:

| Input condition | Return result | Note |
|---|---|---|
| `messages` is empty | `[]` | does not throw |
| `len(messages) <= limit` | a copy containing all messages | preserves order |
| `len(messages) > limit` | exactly the LAST `limit` messages | preserves order |
| `limit = 0` | no return value | throws `ValueError` |
| `limit` is negative | no return value | throws `ValueError` |
| `limit` is `bool` or not `int` | no return value | throws `ValueError` |

- INV: the result is a NEW list; `len(kết quả) = min(len(messages), limit)`; the incoming `messages` does not have a single element changed.
- ERR: only `ValueError`; do not use `IndexError`, do not return an empty list in place of an error.
- KILL: do NOT modify `messages` with `del`, `pop`, `sort`, because the layer above still reuses the original list.

`errors.py`:
- INV: ∀ error class ∈ {`ApiKeyMissing`, `InvalidApiKey`, `InvalidMessage`, `InvalidSession`, `UpstreamError`} ⇒ `issubclass(class, ChatbotError)` and `issubclass(class, Exception)`.
- POST of `UpstreamError`: it has `status: int` and `message: str`, and calls `super().__init__(message)`.

The three ports:
- PRE: inherits `abc.ABC`, every business function is decorated with `@abc.abstractmethod`.
- POST: `MemoryRepository()` ⇒ `TypeError`; `ChatModel()` ⇒ `TypeError`; `ApiKeyStore()` ⇒ `TypeError`.
- INV: the `__abstractmethods__` set of `MemoryRepository` = {`get`, `append`, `reset`}; of `ChatModel` = {`reply`}; of `ApiKeyStore` = {`is_configured`, `get`, `save`}.
- KILL: do NOT add concrete methods to an abstract class, because only the infrastructure layer is allowed to implement them.

## 4.3. File writing rules

- Each function or each class gets its OWN file; every file stays UNDER 100 lines, including test files and fake files.
- Runs on Python 3.11 or later; use annotations like `list[Message]`, `dict[str, list[Message]]`, `Exception | None`.
- Domain does NOT import `flask`, `langchain`, `openai`, `dotenv`, `os`, `pathlib`, `json`; it also does not open files.
- Dependency arrow: interface → application → domain; infrastructure implements ports. Domain does NOT import backwards to application or infrastructure.
- Vietnamese comments and message strings must have FULL diacritics; code names, keywords, and paths stay English.
- Use only the short hyphen, never the en dash.
- Do not put Markdown tables in Python files; tables live only in the prompt and in the opencode report.
- Imports in tests use full paths from the project root: `from src.chatbot.domain.message import Message`; `pytest.ini` must have `pythonpath = .`.
- Fakes in `tests/fakes/` serve tests only; they must not be imported into production code.
- Write tests BEFORE production code; run `py -m pytest -q` to see the RED run, then write the code.

## 4.4. The final opencode report (printed outside the code, in Vietnamese)

The report has exactly four blocks, in this order:

1. **File table**: columns `File | Lines | Status`, one row for every file in 4.1, sorted by the B2 tree.
2. **RED run**: quote verbatim the `short test summary info` block of the `py -m pytest -q` run made before writing the code, with the names of at least 3 red cases.
3. **GREEN run**: quote verbatim the last line of the `py -m pytest -q` run made after writing the code, for example `57 passed in 0.46s`.
4. **Cross-check**: a table mapping each case in B9 to the corresponding test name, concluding `XANH` or `ĐỎ`.

KILL: if after 3 fix rounds there are still red cases, stop immediately, print the round you stopped at, quote verbatim the still-red `short test summary info` and state the reason it is not green yet.

```python
"""Tin nhắn miền. Chỉ chứa dữ liệu thuần, không phụ thuộc thư viện ngoài."""

from dataclasses import dataclass

ROLE_HUMAN = "human"
ROLE_AI = "ai"
ALLOWED_ROLES = (ROLE_HUMAN, ROLE_AI)


@dataclass(frozen=True)
class Message:
    """Một tin trong lịch sử hội thoại. Đóng băng để không sửa ngoài ý muốn."""

    role: str
    content: str

    def __post_init__(self) -> None:
        # PRE: role thuộc ALLOWED_ROLES, content là chuỗi không rỗng.
        # POST: nếu sai thì ném ValueError, đối tượng không được tạo.
        if not isinstance(self.role, str) or self.role not in ALLOWED_ROLES:
            raise ValueError("role phải là 'human' hoặc 'ai'")
        if not isinstance(self.content, str) or self.content.strip() == "":
            raise ValueError("content phải là chuỗi không rỗng")
```

## 5.2. `src/chatbot/domain/trim_history.py`

```python
"""Cắt lịch sử còn N tin cuối. Không sửa danh sách truyền vào."""

from .message import Message


def trim_history(messages: list[Message], limit: int) -> list[Message]:
    """Trả list MỚI chứa tối đa `limit` tin CUỐI, giữ nguyên thứ tự."""
    # PRE: messages là list[Message], limit là số nguyên > 0.
    # POST: len(kết quả) = min(len(messages), limit), thứ tự không đổi.
    # ERR: limit sai kiểu hoặc limit <= 0 thì ném ValueError.
    if isinstance(limit, bool) or not isinstance(limit, int) or limit <= 0:
        raise ValueError("limit phải là số nguyên lớn hơn 0")
    if len(messages) == 0:
        return []
    return list(messages[-limit:])
```

```python
import abc

from ..message import Message


class MemoryRepository(abc.ABC):
    """Kho lịch sử theo session_id."""

        """Xoá sạch một phiên; phiên chưa tồn tại vẫn coi là thành công."""
```

# 6. Notices:

- Do NOT import `flask`, `langchain`, `openai`, `dotenv`, `os`, `pathlib`, `json` in `domain/`, because `test_no_forbidden_import` scans every import line and will go red immediately.
- Do NOT use raw string comparison to scan imports in tests, for example the style `word in dong`, because `from ..ports import x` or `close` will be misdetected as `os` and cause a false red.
- Do NOT let `domain/` depend back on `application/` or `infrastructure/`, because the dependency arrow is interface → application → domain.
