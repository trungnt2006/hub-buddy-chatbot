## 3b. Short definitions

- **opencode**: an AI programming assistant that runs in a command-line window, reads the prompt, then generates source code according to the specification.
- **API**: application programming interface, here an external service that returns text.
- **endpoint**: an HTTP path with a determined method and body format, for example `/api/chat`.
- **venv**: Python virtual environment, created with `py -m venv .venv`, isolating libraries for the project.
- **pytest**: Python testing library, run with `py -m pytest -q`.
- **DDD**: domain-driven design, layering by role and keeping the dependency arrows one-way.
- **TDD**: test-driven development, writing a red test first then writing code to make it green.
- **MUI**: React UI library from Material, used via the UMD build from CDN in P7.
- **formal spec**: formal specification using the PRE conditions, POST postconditions, INV invariants, ERR error rules, and KILL stop conditions.
- **first-run**: the first execution when the machine has no API key, where the system must ask for the key and then run immediately.
- **use case**: a function in the application layer describing one business behaviour, for example `send_message`.
- **fake**: an object substituting real behaviour in tests, for example `FakeChatModel`.
- **payload**: the body part of an HTTP request carrying data.
- **traceback**: the full text of the internal error chain, absolutely never returned to the browser.

User lock-in 2026-10-07: the prompt IS the blueprint; an AI that reads all 10 prompts (P0 through P9) can build the chatbot; each prompt is at least 5,000 words, written in formal specification style, covering every case; the first thing to do when the chatbot runs for the first time is TO ASK FOR THE API KEY, send it to the server, the server stores it, and then it runs.

## B1. Goal and first-run flow
- Platform: Windows 11, PowerShell, Python invoked via `py`, coding assistant is opencode, responding model is `gpt-4o-mini` via the OpenAI API (external API).
- First-run flow:
  1. The learner runs `py run.py`; the server starts at `http://127.0.0.1:2610` WHEN THERE IS NO API KEY YET (must not crash).
  2. The browser opens the page; `main.js` calls `GET /api/setup/status`.
  3. It returns `{"configured": false}` ⇒ show the MUI dialog "Nhập khóa API" (password field + Save button).
  4. The learner pastes the key, clicks Save ⇒ `POST /api/setup` with `{"api_key": "<key>"}`.
  5. The server validates the key format, writes it into the `.env` file (line `OPENAI_API_KEY=`) atomically, updates the process memory, returns `{"ok": true}`; it must NEVER return the key.
  6. The page closes the dialog and shows the chat frame; chat runs immediately, no restart needed.
  7. Subsequent runs: `status` returns `{"configured": true}` ⇒ go straight to the chat frame.
- The key lives only in `.env`; not in logs, not in `memory.json`, not in responses, not in errors.

## B4. Domain
- `Message`: frozen dataclass `role: str` (only `"human"` or `"ai"`), `content: str` (non-empty). Wrong ⇒ `ValueError`.
- `trim_history(messages: list[Message], limit: int) -> list[Message]`: returns the LAST `limit` messages, preserving order; `limit <= 0` ⇒ `ValueError`; empty list ⇒ empty; fewer than `limit` ⇒ return all; does not modify the input list.
- `errors.py`: `ApiKeyMissing`, `InvalidApiKey`, `InvalidMessage`, `InvalidSession`, `UpstreamError(status: int, message: str)`; all inherit `ChatbotError(Exception)`.
- Ports (abstract classes `abc.ABC`):
  - `MemoryRepository`: `get(session_id: str) -> list[Message]`, `append(session_id: str, messages: list[Message]) -> None`, `reset(session_id: str) -> None`.
  - `ChatModel`: `reply(system_prompt: str, history: list[Message], user_text: str) -> str`.
  - `ApiKeyStore`: `is_configured() -> bool`, `get() -> str`, `save(api_key: str) -> None`.

## B5. Application (use cases, one function per file)
- `validate_session_id(session_id) -> str`: matches `^[A-Za-z0-9-]{8,64}$`, otherwise `InvalidSession`.
- `validate_message(text) -> str`: trims leading and trailing whitespace; empty ⇒ `InvalidMessage`; longer than 4000 characters ⇒ `InvalidMessage`.
- `validate_api_key(api_key) -> str`: trims whitespace; length 20 to 200; only printable ASCII characters, NO whitespace inside; wrong ⇒ `InvalidApiKey`. Do NOT check the vendor prefix.
- `get_setup_status(store) -> dict`: `{"configured": store.is_configured()}`.
- `configure_api_key(store, api_key) -> None`: `store.save(validate_api_key(api_key))`.
- `send_message(repo, model, store, system_prompt, max_messages, session_id, text) -> str`:
  1. `sid = validate_session_id(...)`, `msg = validate_message(...)`.
  2. `store.is_configured()` false ⇒ `ApiKeyMissing`.
  3. `history = trim_history(repo.get(sid), max_messages)` (if empty, skip trimming).
  4. `reply = model.reply(system_prompt, history, msg)`.
  5. `repo.append(sid, [Message("human", msg), Message("ai", reply)])` ONLY after `reply` exists; a model error ⇒ write NOTHING to memory.
  6. return `reply`.
- `reset_conversation(repo, session_id) -> None`: validate `session_id`, then `repo.reset(sid)`; resetting a non-existent session is a silent success.

## B6. Infrastructure
- `atomic_write_text(path, text)`: writes to a temp file in the same directory then `os.replace`; creates the parent directory if missing; on error ⇒ delete the temp file, rethrow the error.
- `atomic_write_json(path, data)`: `json.dumps(ensure_ascii=False, indent=2)` then `atomic_write_text`.
- `JsonMemoryRepository(path)`: uses `threading.Lock`; file format `{"<session_id>": [{"role": "human", "content": "..."}]}`; missing file ⇒ empty; corrupt file (invalid JSON) ⇒ rename to `memory.json.corrupt-<timestamp>` then start empty, MUST NOT crash; `append` reads then writes atomically within the same lock; stores ALL messages (trimming happens only when reading for the model).
- `load_system_prompt(path) -> str`: reads UTF-8; missing file ⇒ returns a short Vietnamese default, MUST NOT crash; empty file ⇒ also the default.
- `EnvApiKeyStore(env_path)`: `is_configured()` is true exactly when `get()` is non-empty; `get()` reads `OPENAI_API_KEY` from the `.env` file (and from `os.environ` if the file is missing); `save(key)` rewrites the `.env` file keeping the other lines intact, replacing or appending exactly one line `OPENAI_API_KEY=<key>`, writes atomically, updates `os.environ`; write error ⇒ rethrow, MUST NOT leave a half-written file.
- `mask_secret(value) -> str`: returns `"****"` plus the last 4 characters when the length is 12 or more; otherwise `"****"`; used for logs, MUST NEVER write the real key.
- `LangChainChatModel(settings, store)`: each `reply` builds `ChatPromptTemplate.from_messages([("system", system_prompt), MessagesPlaceholder("history"), ("human", "{input}")])`, attaches `ChatOpenAI(model=settings.openai_model, temperature=settings.openai_temperature, timeout=settings.openai_timeout, api_key=store.get())`, converts `Message` to `HumanMessage`/`AIMessage`, returns `.content`; OpenAI error ⇒ `UpstreamError(*map_openai_error(exc))`; the key is read AGAIN on every turn so that no restart is needed after `/api/setup`.
- `map_openai_error(exc) -> tuple[int, str]`: `AuthenticationError`→401 "Khóa API không đúng, nhập lại"; `RateLimitError` (HTTP 429)→503 "Hệ thống đang quá tải, thử lại sau"; `APITimeoutError`→504 "Mô hình trả lời quá lâu"; `APIConnectionError`→502 "Không kết nối được dịch vụ mô hình"; otherwise→500 "Có lỗi không mong đợi".

## B7. Interface (Flask)
- `create_app(deps) -> Flask`: `deps` comprises `settings`, `repo`, `model`, `store`, `system_prompt_loader`; registers 5 routes; `MAX_CONTENT_LENGTH = 16 * 1024`; error handling funnels into JSON.
- Every error returns `{"error": "<code>", "message": "<Vietnamese>"}`; MUST NEVER return a stack trace.
- `require_localhost`: `request.remote_addr` not in `{"127.0.0.1", "::1"}` ⇒ 403 `forbidden`; applied to `/api/setup`.
- `require_json`: missing `Content-Type: application/json` or body not a JSON object ⇒ 415 or 400.

```python
from flask import jsonify
from werkzeug.exceptions import HTTPException


def error_response(status: int, code: str, message: str):
    return jsonify({"error": code, "message": message}), status


def register_error_handlers(app) -> None:
    @app.errorhandler(400)
    def bad_request(_error):
        return error_response(400, "bad_request", "Thân yêu cầu không hợp lệ")

    @app.errorhandler(404)
    def not_found(_error):
        return error_response(404, "not_found", "Không tìm thấy đường dẫn")

    @app.errorhandler(405)
    def wrong_method(_error):
        return error_response(405, "method_not_allowed", "Phương thức không được phép")

    @app.errorhandler(413)
    def too_large(_error):
        return error_response(413, "payload_too_large", "Nội dung gửi lên vượt 16 KB")

    @app.errorhandler(Exception)
    def unhandled(error):
        if isinstance(error, HTTPException):
            return error
        app.logger.error("Lỗi không mong đợi: %s", type(error).__name__)
        return error_response(500, "internal_error", "Có lỗi không mong đợi")
```

    pass


def require_json():
    def guard() -> None:
        if request.mimetype != "application/json":
            raise UnsupportedMediaType()
        if not isinstance(request.get_json(silent=True), dict):
            raise MalformedJson()

    return guard


def to_response(exc):
    if isinstance(exc, UnsupportedMediaType):
        return error_response(415, "unsupported_media_type", "Phải gửi Content-Type: application/json")
    return error_response(400, "bad_request", "Thân yêu cầu không phải đối tượng JSON")

```python
import time

from flask import jsonify, request

from src.chatbot.application.send_message import send_message
from src.chatbot.domain.errors import ApiKeyMissing, InvalidMessage, InvalidSession, UpstreamError
from src.chatbot.interface.json_error import error_response
from src.chatbot.interface.require_json import MalformedJson
from src.chatbot.interface.require_json import UnsupportedMediaType
from src.chatbot.interface.require_json import require_json
from src.chatbot.interface.require_json import to_response as json_to_response

UPSTREAM_ERRORS = {
    401: ("api_key_invalid", "Khóa API không đúng, nhập lại"),
    502: ("upstream_unavailable", "Không kết nối được dịch vụ mô hình"),
    503: ("upstream_busy", "Hệ thống đang quá tải, thử lại sau"),
    504: ("upstream_timeout", "Mô hình trả lời quá lâu"),
}


def register(app, deps) -> None:
    settings, repo = deps["settings"], deps["repo"]
    model, store = deps["model"], deps["store"]
    load_prompt = deps["system_prompt_loader"]

    @app.post("/api/chat")
    def chat():
        try:
            require_json()()
        except UnsupportedMediaType as exc:
            return json_to_response(exc)
        except MalformedJson as exc:
            return json_to_response(exc)
        payload = request.get_json(silent=True)
        session_id = payload.get("session_id", "")
        text = payload.get("message", "")
        system_prompt = load_prompt(settings.system_prompt_file)
        started = time.monotonic()
        try:
            reply = send_message(repo, model, store, system_prompt, settings.max_messages, session_id, text)
        except ApiKeyMissing:
            return error_response(409, "api_key_missing", "Chưa nhập khóa API")
        except InvalidMessage:
            return error_response(400, "invalid_message", "Tin nhắn rỗng hoặc quá 4000 ký tự")
        except InvalidSession:
            return error_response(400, "invalid_session", "Mã phiên không hợp lệ")
        except UpstreamError as exc:
            code, note = UPSTREAM_ERRORS.get(exc.status, ("internal_error", "Có lỗi không mong đợi"))
            return error_response(exc.status, code, note)
        if not reply.strip():
            return error_response(502, "empty_reply", "Mô hình trả lời rỗng, hãy thử lại")
        ms = int((time.monotonic() - started) * 1000)
        return jsonify({"reply": reply, "model": settings.openai_model, "ms": ms})
```

## ERR:

**ERR.1 - 415 appears although the test sends well-formed JSON.** Symptom: `test_protocol_errors_return_json` is red on all three paths. Cause: the test uses `data=` without a content type, or `require_json` compares the full header string instead of `request.mimetype`. Fix: in the test use `json=` when you want 200 and `data=` when you want 415; in `require_json` compare only `request.mimetype`. ```python
"""Đổi mọi lỗi thành JSON thống nhất, không lộ stack trace."""

from flask import jsonify
from werkzeug.exceptions import HTTPException

from src.chatbot.domain.errors import (
    ApiKeyMissing,
    ChatbotError,
    InvalidApiKey,
    InvalidMessage,
    InvalidSession,
    UpstreamError,
)

EMPTY_REPLY_STATUS = 502
EMPTY_REPLY_CODE = "empty_reply"
EMPTY_REPLY_MESSAGE = "Mô hình trả về nội dung rỗng."

RULES = (
    (InvalidSession, 400, "invalid_session", "Mã phiên không hợp lệ."),
    (InvalidMessage, 400, "invalid_message", "Nội dung tin không hợp lệ."),
    (InvalidApiKey, 400, "invalid_api_key", "Khóa API không đúng hình thức."),
    (ApiKeyMissing, 409, "api_key_missing", "Chưa nhập khóa API."),
)

UPSTREAM_CODES = {
    401: "invalid_api_key",
    502: "upstream_unreachable",
    503: "rate_limited",
    504: "upstream_timeout",
}


def error_payload(code, message):
    """Khoả khóa đúng hai trường của mọi phản hồi lỗi."""
    return {"error": code, "message": message}


def resolve_chatbot_error(exc):
    """Ánh xạ lỗi tầng domain sang cặp (status, code, message)."""
    if isinstance(exc, UpstreamError):
        if exc.message == EMPTY_REPLY_MESSAGE:
            return EMPTY_REPLY_STATUS, EMPTY_REPLY_CODE, exc.message
        code = UPSTREAM_CODES.get(exc.status, "upstream_error")
        return exc.status, code, exc.message
    for cls, status, code, message in RULES:
        if isinstance(exc, cls):
            return status, code, message
    return 500, "internal_error", "Có lỗi không mong đợi."


def register_error_handlers(app):
    """Gắn bốn trình xử lý lỗi vào ứng dụng Flask."""

    @app.errorhandler(ChatbotError)
    def handle_chatbot_error(exc):
        status, code, message = resolve_chatbot_error(exc)
        return jsonify(error_payload(code, message)), status

    @app.errorhandler(413)
    def handle_too_large(_exc):
        return jsonify(error_payload("payload_too_large", "Thân yêu cầu vượt quá 16 KB.")), 413

    @app.errorhandler(HTTPException)
    def handle_http_exception(exc):
        code = exc.name.lower().replace(" ", "_")
        return jsonify(error_payload(code, exc.description)), exc.code

from flask import jsonify, request

from src.chatbot.interface.json_error import error_payload


def require_json():
    """Trả None khi đạt, trả (response, status) khi không đạt."""
    if request.mimetype != "application/json":
        body = error_payload("unsupported_media_type", "Thiếu Content-Type: application/json.")
        return jsonify(body), 415
    if not isinstance(request.get_json(silent=True), dict):
        body = error_payload("invalid_json", "Thân yêu cầu phải là đối tượng JSON.")
        return jsonify(body), 400
    return None

"""POST /api/chat: nhận tin, trả câu trả lời, không nhận lịch sử từ client."""

import time

from src.chatbot.application.send_message import send_message

@chat_bp.post("/api/chat")
def chat():
    """Chỉ đọc hai trường message và session_id, bỏ qua trường thừa."""
    bad_request = require_json()
    if bad_request is not None:
        return bad_request
    deps = current_app.config["deps"]
    payload = request.get_json(silent=True)
    started = time.perf_counter()
    reply = send_message(
        deps["repo"],
        deps["model"],
        deps["store"],
        deps["system_prompt_loader"](),
        deps["settings"].max_messages,
        payload.get("session_id", ""),
        payload.get("message", ""),
    )
    elapsed_ms = int((time.perf_counter() - started) * 1000)
    model_name = deps["settings"].openai_model
    return jsonify({"reply": reply, "model": model_name, "ms": elapsed_ms})

def resolve_static_dir(deps):
    """Lấy thư mục static, suy từ MEMORY_FILE khi deps không khai báo."""
    given = deps.get("static_dir")
    if given is not None:
        return Path(given)
    memory_file = Path(deps["settings"].memory_file)
    return memory_file.resolve().parent / "static"


def create_app(deps) -> Flask:
    """Khoá chặt cấu hình, nạp blueprint, đăng ký xử lý lỗi."""
    app = Flask(__name__, static_folder=str(resolve_static_dir(deps)), static_url_path="/static")
    app.config["MAX_CONTENT_LENGTH"] = MAX_CONTENT_LENGTH
    app.config["deps"] = deps
    for blueprint in (health_bp, setup_status_bp, setup_bp, chat_bp, reset_bp):
        app.register_blueprint(blueprint)
    register_error_handlers(app)

    @app.get("/")
    def index():
        """Phục vụ trang nhập khóa API và khung chat."""
        return send_from_directory(app.static_folder, INDEX_FILE)

    return app

# 6. Notices:

- Ban `debug=True` in `run.py`: turning on debug mode leaks the stack trace into the browser and breaks INV2; the Flask `reloader` (`use_reloader`) must stay disabled too, because a double start writes `memory.json` twice and corrupts it.
- Ban `app.run()` in any file other than `run.py`: every import would occupy the port and the tests could not run.
- Ban feeding `str(exc)` of an OpenAI error straight into the response: the error text may contain the key prefix, use `map_openai_error`.
- Ban printing the key value to the console in `run.py` and in `json_error`: the key may live only in `.env` and in process memory.
- Ban returning `{"error", "message", "status"}`: the client needs only two keys, an extra key breaks the JSON contract.
- Ban storing secrets directly in `app.config`: it holds only `deps`, never keys.
- Ban passing `history` from the client into `send_message`: history comes only from `repo`, otherwise an attacker can forge the conversation.
- Ban skipping `require_localhost` on `/api/setup`: that route receives a secret from the user, opening it beyond localhost exposes a weakness.
- Ban a `MAX_CONTENT_LENGTH` larger than `16 * 1024`: an unbounded body hangs the process, this is a mandatory boundary case.
- Ban `except Exception: pass` in routes: errors must go through `register_error_handlers` to return JSON, never be swallowed.
- Warning: `FakeApiKeyStore.save` updates `os.environ` inside the test process, so use `tmp_path` and let no environment variable leak into other tests.
- Warning: `EnvApiKeyStore` prefers `os.environ` when the `.env` file is missing, so the "delete the file and lose the key" test goes red if the environment variables are not cleaned first.
- Warning: placing the `pytest` import after `sys.path.insert` in `run.py` is mandatory because `src` is not yet on the system path.
- Warning: renaming a blueprint after `register_blueprint` causes a duplicate-name error, keep the five defined names unchanged.
- Warning: `settings.openai_model` must be read when the route runs, not at `import` time, otherwise the response-shape tests become hard to maintain.
- Ban `innerHTML` and `dangerouslySetInnerHTML` in every `.js` file: adversarial input must still display verbatim, so prompt injection, an empty message, a 10 000 character message and HTML in a message all go through `textContent` or `escape`, React escapes the characters itself.
- Ban creating files outside the B2 directory tree: no private `conftest.py`, no `AGENTS.local.md`, no shared `helpers.py`.
- Ban putting a real API key into tests, into `.env.example`, into the report: the sample key is always `TEST_KEY_` followed by 20 x characters.
